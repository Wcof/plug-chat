# Plug Chat 实施与验收

## 用户目标

在 APP 内打开、查看和操作多个豆包、千问、DeepSeek、ChatGPT、Gemini 网页 Chat；把指定单个 Chat 的内容发送到指定 Session，让 Session 读取并继续对话。减少重复输入；通过选取范围和增量去重减少重复上下文，不能保证模型实际计费 Token 必然下降。

## 已确定的决策

1. 采用宿主无关核心与宿主适配层。先核对 DSH 原生 Browser/Session 接口；不假造其他 APP 的插件 API。
2. 面板直接使用宿主 React 和原生浏览器能力，避免跨站 iframe 限制及不必要的第二套浏览器。
3. Chat 内容只读提取，选择后传入指定 Session；传输包含来源、角色、消息范围和“外部资料”的边界提示。
4. 支持完整或所选消息、最近若干轮、按目标 Session 增量发送。增量基线只在宿主确认提交后推进；失败不消耗基线。
5. 页面选择器独立适配，拒绝整页文本回退、空内容与未知页面。界面标注只包含页面已加载内容。
6. 新项目使用 TypeScript；构建选用少量工具和宿主已有运行时，生产代码不重复打包框架。

入口：`/Users/ldh/Downloads/project/DeepSeekBox/AGENTS.md`、`ARCHITECTURE.md`、`docs/hosts/dsh-spec.md`、本机 DSH 安装源码。

允许：读取源码和官方公开资料。禁止：修改参考项目、真实 profile、Session 内容或凭证。
交付：精确 API、文件证据、最小样例、兼容条件与未验证项。

### C：核心协议与上下文（待接口固定后实施）

目标：单 Chat 来源和消息验证、选择/最近/增量策略、传输去重与来源边界。仅修改 `src/core/` 和对应测试。

### P：网页提取适配（待类型固定后实施）

### U：原生面板与宿主适配（主 Agent）

目标：多 Chat、切换、加载/错误/空态、提取预览、范围选择、真实 Session 列表和提交反馈。布局采用紧凑三栏：Chat 列表、原生网页、可收起的发送到 Session 面板。

### V：交付验证与仓库（主 Agent + 只读审查）

类型检查、核心/DOM/适配器测试、打包校验、原生宿主隔离验证与 UI 检查。记录真实验证与未验证范围；创建用户 GitHub 仓库并明确代码是否已提交/推送。

## 实测边界

网站 URL 已由用户提供；网页版本会变化，选择器测试只保证夹具行为。真实网站登录、流式输出、虚拟化历史和宿主沙箱须按实际环境验证。不得将任一未完成路径报告为全部支持。
